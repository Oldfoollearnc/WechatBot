AI 编程前提准备指南

节省 Token · 提高质量 · 高效协作

💡 一、节省 Token
1

.claudeignore — 写对

排除构建产物和依赖目录，搜索结果干净

# Build outputs
bin/  obj/  .vs/
# Dependencies
node_modules/  *.log
2

项目结构清晰

文件职责单一，模块化设计，读的上下文越精准

❌ 2000行的 God Class
✅ 200行的单一职责文件

读的上下文越精准 → Token越少
3

避免重复说明

稳定需求写进 CLAUDE.md，一次配置永久生效

# CLAUDE.md
- 测试用 xUnit
- 异步必须加 CancellationToken
- commit用英文 type(scope): desc
4

问题要具体

精确描述目标，避免大范围搜索

❌ "帮我优化这个项目"
✅ "DoWork方法响应慢，帮我优化"

精准定位 → 省50%以上Token
🎯 二、提高代码质量
1

.editorconfig — 统一风格

所有编辑器输出格式一致，团队协作无冲突

[*]
indent_style = space
indent_size = 4
end_of_line = crlf
charset = utf-8
2

CLAUDE.md — 技术约束

写清技术栈、代码规范、架构边界

# 技术栈
.NET 8, WPF, Dapper
# 规范
PascalCase公共 / _camelCase私有
# 架构
AutomationEngine是核心调度器
3

测试先行

先写测试再写代码，改完立刻验证，不怕改出 bug

[Fact]
public void DoWork_ShouldComplete()
{
    // 有测试 → 改代码不怕改出bug
    // 质量远高于"写完再补测试"
}
4

小步提交

一次改一个小功能，改动越小出错越少

❌ "把整个项目重构了"
✅ "重构 AutomationEngine"

范围小 → 出错少 → Review容易
